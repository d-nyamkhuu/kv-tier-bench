    Simulation assumptions

    By default the replay warms the caches for 20 minutes and then measures 60 minutes; a cold start measures the first 60 minutes from empty caches. Each point is the average TTFT of requests arriving in that minute, including queueing. Varied lengths draw each message and reply from a lognormal distribution with the set mean (coefficient of variation 0.5, or 1.5 when long-tailed). Distinct system prompts share the set length, and each new chat picks one with Zipf popularity. Bursty arrivals start new chats at twice the mean rate for 2 minutes of every 6 and half of it otherwise. LMCache MP eagerly saves complete prompt chunks by default. Host memory and bounded local SSDs check occupancy every second. At 80% capacity the controller evicts the oldest 20% of resident entries. GPU cache uses its own capacity limit.

    The model uses the smallest fitting parallel layout on the selected hardware, preferring a single node per instance. Decode runs on separate nodes of the same GPU type. Conversations share a system prompt and grow by the message and reply lengths set in workload details. Think time starts at the last token of the previous reply. Longer replies or queues can reduce the number of follow-ups arriving within the hour. Decode batches form from requests ready at each step. The random seed is fixed across runs.

    Prompt KV becomes available after prefill. Each private SSD and object-store adapter makes a batch readable after its modeled write completes. Optional reply chunks become eligible after the last token. Concurrent transfers queue for the same disk or network interface. Peer reads occupy both nodes’ interfaces. The hourly estimate adds the costs of all enabled backing tiers. Each block is looked up in GPU memory, local CPU memory, local SSD, then S3 and peer CPU in the selected order. Missing blocks are recomputed. The SSD slider sets provisioned cache capacity per node. Each node is billed for that capacity at the selected SSD rate. Object storage uses the write rate and one hour of retention, plus transfer fees and estimated PUT, GET and HEAD charges at US East (N. Virginia) rates. A cold metadata lookup adds one round trip for a parallel batch of HEAD requests. Each object group and rank is billed separately. Costs include the work required to finish requests admitted during the hour. The serving cost adds the provisioned prefill GPUs and the decode GPUs needed at peak, at on-demand prices, to the backing tiers. Host memory is outside this estimate. Prefill runs in continuous batches: each step serves waiting requests first come, first served up to the batch budget, splitting longer prompts across steps, and costs one read of the model weights (at most the calibrated 52 ms per-request overhead) plus the compute of its tokens. The rest of that overhead delays each request without occupying the GPU, so a request alone in its step keeps the measured one-at-a-time TTFT. Cache lookups and loads run without blocking other requests, as LMCache's multi-process connector does by default.
